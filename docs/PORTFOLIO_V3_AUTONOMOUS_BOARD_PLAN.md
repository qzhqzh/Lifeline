# Lifeline「AI 自治推进大板 V3」执行方案

> 稳定计划前缀：`lifeline-autonomous-board-v1`
> 目标：把 Lifeline 从传统项目看板升级为面向单一项目所有者与多个 AI Agent 的自治推进控制平面。

## 1. 产品结论

Lifeline 继续保持 `Project → Phase → Task` 两级排期。AI 负责规划、重排、领取、推进和复核，人主要观察结果、异常和调度原因。

本期优先解决四件事：

1. 数据可信：任务、阶段和项目状态由真实任务与完成记录派生。
2. 自动排期：使用动态批次代替大量人工日期维护。
3. Agent 协作：支持原子领取、租约、一次完成上报和独立复核。
4. 决策效率：首页直接回答“谁在推进、下一步是什么、为什么、哪些项目停了”。

暂不建设多人评论通知、第三层任务结构、完整 Gantt、强制 Sprint、任意自定义视图，以及 React、PostgreSQL、Temporal 迁移。

## 2. 核心模型

```text
ProjectHealth:
ON_TRACK | AT_RISK | BLOCKED | STALLED | DORMANT | COMPLETE

DispatchBatch:
NOW | NEXT | RESERVE | BACKLOG

DispatchDecision:
batch、rank、reasonCodes、policyVersion、decidedAt

ClaimLease:
runId、agentId、modelRef、claimedAt、leaseExpiresAt
```

默认自治策略：

- 高算力执行槽 1 个、中算力 1 个、低算力 2 个、独立复核槽 1 个。
- 同一项目默认最多运行 1 个改动型任务；明确可并行且无文件冲突时可以突破。
- `scheduledFor` 仅表示真实硬期限，普通任务进入动态批次。
- REVIEW 超过 24 小时标记风险；存在未完成任务且 72 小时无真实推进时标记停滞。
- 订阅余额只提供提醒，在采集可信度稳定前不直接改变执行槽。

所有既有接口保持兼容，只增加 `computedStatus`、`health`、`lastProgressAt`、`dispatch` 和 `decision`。

## 3. 接口范围

新增 REST：

- `GET /api/portfolio/dispatch`
- `POST /api/portfolio/rebalance`
- `POST /api/agent-runs/claim`
- `POST /api/runs/:id/lease`
- `POST /api/work-items/:id/restore`

新增 MCP：

- `lifeline_get_dispatch_board`
- `lifeline_claim_next_task`
- `lifeline_extend_task_lease`
- `lifeline_restore_task`

继续复用：

- `lifeline_submit_completion`
- `lifeline_verify_task`
- 现有 Project、Phase、Task 创建、修改、排序和取消工具。

Agent 权限范围：

```text
portfolio:read
schedule:write
task:claim
completion:write
verification:write
```

## 4. 实施排期

### S14 · 让排期数据先可信

1. 派生阶段状态与项目健康度
   - 从任务、依赖、完成记录和时间推导阶段状态、当前任务、最近真实推进及项目健康度。
   - 大板、详情页与 API 使用同一套结果。

2. 建立可解释的调度决策引擎
   - 排除 DEFERRED、BLOCKED、契约不完整、依赖未满足和已领取任务。
   - 结合战略价值、优先级、星标、算力、风险和硬期限排序。
   - 返回结构化原因，不展示内部思考过程。

3. 修复当前排期漂移
   - 取消已失去意义的“理解现有控制平面与首页链路”。
   - 保留 S5 周期扫描任务，取消重复普通扫描任务。
   - 将任务全部验收的阶段修正为完成。
   - 所有取消、修正与恢复都保留审计记录。

### S15 · 重做首页决策层与交互手感

1. 建立动态推进批次
   - 自动维护 NOW、NEXT、RESERVE、BACKLOG。
   - 状态或容量变化后自动重算，不要求人工拖入日期。

2. 重构首页信息层级
   - 保留暗色品牌和 3D Logo。
   - 第一屏展示正在执行、下一批、待复核、停滞项目和剩余执行槽。
   - “计划任务”更名为“已推迟”。
   - 单一推荐升级为执行中、下一批高算力、下一批低算力三个推荐位，并显示简短原因。
   - 推进轨迹默认收起，只保留摘要。

3. 提升大板视觉与刷新稳定性
   - 左侧项目区固定，默认聚焦当前阶段及相邻阶段。
   - 正文不小于 12px，任务标题不小于 14px。
   - 首页卡片只保留标题、状态、实际或推荐 Agent、算力和估时，详细验收、依赖与证据进入右侧抽屉。
   - 详情页宽屏每行 5 张固定比例卡片，响应式降为 4/2/1 列。
   - 富悬浮层按可用空间选择上下左右，拖动时关闭。
   - 10 秒刷新采用 keyed 更新，保持泳道高度、滚动位置、焦点和拖拽状态。
   - 动效限制在 120–180ms 的透明度与轻位移，并兼容 `prefers-reduced-motion`。

### S16 · 打通多 Agent 自治执行

1. 实现原子任务领取
   - Agent 按能力、算力和风险范围领取 NEXT 任务。
   - 一次事务完成选取、Run 创建和租约写入，避免重复领取。

2. 实现轻量租约与失败恢复
   - 默认租约为 `max(30 分钟, 预计耗时 × 2)`，最长 8 小时。
   - Agent 不持续汇报；长任务仅在必要时延长租约。
   - 租约到期后任务安全返回 NEXT，不制造虚假失败。

3. 保留一次完成上报与独立复核
   - 执行 Agent 只提交一次结果，任务进入 REVIEW。
   - 复核 Agent 独立领取 REVIEW 任务，根据测试、审查或批准证据完成验证。

4. 开放 Agent 接口与权限边界
   - 提供局域网 MCP 访问和范围令牌。
   - AI 可创建、重排、推迟、取消和恢复未执行任务；生产发布、凭证和数据删除继续受安全门禁。

### S17 · 用历史结果优化下一轮排期

1. 建立真实效率指标
   - 按项目、任务类型、模型和算力统计吞吐量、执行与复核耗时、失败/阻塞/重开率、估时偏差、执行槽饱和度和无上报区间。

2. 自动校准推荐
   - 只有样本量达到阈值后才调整模型、算力和估时。
   - 样本不足时继续使用规则默认值，并明确标记低置信度。

3. 增加“为什么这样排”视图
   - 展示最近调度变化、原因、效果和可撤销入口，不展示内部思考过程。

4. 文档与发布收口
   - 更新 OpenAPI、MCP 文档、自治策略说明和恢复手册。
   - 完成一次全量检查、一次服务重建与重启。

## 5. 验收标准

- 大板、详情页和 API 对当前任务、阶段状态、项目健康度保持一致。
- 首页第一屏无需进入详情即可看清正在执行、下一批、选择原因、待复核和停滞项目。
- 至少 3 个 Agent 并发领取、执行、完成上报和复核时不重复领取、不覆盖状态。
- 租约过期任务安全回到 NEXT；迟到 Agent 不能覆盖新执行结果。
- 调度调整可解释、可审计、可恢复，不记录 Agent 内部思考。
- 自动刷新不改变泳道高度、滚动位置、焦点和拖拽状态。
- 1920×1080、1366×768、390×844 三种视口通过真实浏览器检查。
- 每个边界只运行针对性测试，整批最后只运行一次 `npm run check`，然后重建、重启并检查健康状态。

## 6. 数据与发布安全

- 当前未提交工作区内容全部视为用户资产，不清理、不重置、不覆盖。
- 影子调度先只计算不写入；结果稳定后再启用自动重排。
- 取消、恢复、领取、租约和调度变化均写入审计事件。
- 不删除数据库迁移或持久数据，不扩大外部系统权限。
- 提交、推送、PR、合并和部署必须分别获得用户明确授权。
